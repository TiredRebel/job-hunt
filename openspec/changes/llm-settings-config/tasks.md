  - Added `LlmServiceError` (carries `status` + `message`) to the port file — thrown by the client on any non-2xx, caught by the service to map to the right NestJS exception. Dropped the originally-sketched `PipelineOverrideInput` type: `model`/`temperature` don't change spelling between camelCase and snake_case, so `pipelineOverrides` is typed `Record<string, unknown>` end-to-end and passed through untouched — deep validation stays on the LLM service, matching D6's "dumb proxy" intent and avoiding a needless cast.
- [x] 2.2 `http-llm-admin.client.ts`: implement the four new methods (snake→camel mapping as the file already does; request bodies map camel→snake; create surfaces the LLM service's 409 distinctly so the service layer can throw `ConflictException`); delete the `/health`-fetch `testConnection`
  - `updateProvider` uses `Object.hasOwn(patch, 'apiKeyEnv')` to decide whether to include the key in the outbound body at all, preserving the omitted-vs-explicit-null distinction all the way from the HTTP request through to the LLM service's own `model_fields_set` check.
- [x] 2.3 DTOs: `CreateLlmProviderDto` (slug `@Matches(/^[a-z0-9-]+$/)`, kind `@IsIn([...])`, baseUrl `@IsUrl`, defaultModel `@IsString @IsNotEmpty`, apiKeyEnv `@IsOptional @IsString`), `UpdateLlmProviderDto` (`baseUrl?`/`defaultModel?` optional non-empty, `apiKeyEnv?` nullable string, `pipelineOverrides?` `@IsObject` — deep validation stays on the LLM service, the gateway is a proxy; document that in the DTO docstring), response DTOs `ProviderTestResponse`/`ModelListResponse` with `@ApiProperty` (no `default:` values in decorators — see design Migration Plan for the openapi-typescript quirk)
  - Deliberate deviation from the plan: `baseUrl` uses `@IsString() @IsNotEmpty()`, **not** `@IsUrl()`. `class-validator`'s `@IsUrl()` defaults to `require_tld: true`, which would reject legitimate values like `http://localhost:11434` or `http://ollama:11434` — the norm for this domain (Docker/local LLM backends), unlike `sources.dto.ts` where base URLs are always public websites. The LLM service's own `CreateProviderRequest.base_url` likewise only enforces `min_length=1`, so this keeps the gateway from being stricter than the service it fronts. `kind` is required (not optional/defaulted) in the DTO — the "defaults to openai-compatible" behavior lives in the web Select component per D4, keeping the DTO's OpenAPI shape simple and sidestepping the `default:`-makes-it-required `openapi-typescript` quirk entirely.
- [x] 2.4 `LlmAdminService` + `LlmAdminController`: `POST providers` (201; ConflictException on duplicate), `POST providers/:slug/test` (`@HttpCode(200)`), `GET providers/:slug/models`, `PATCH providers/:slug`; remove the `providers/test-connection` route/service method; LLM-service transport failure → `BadGatewayException` (502) on all four
  - One shared private `raiseFor(error, slug)` mapper in the service handles all four methods' error translation (404→NotFoundException, 409→ConflictException, 400/422→BadRequestException, else→BadGatewayException) rather than four near-duplicate try/catch bodies.
